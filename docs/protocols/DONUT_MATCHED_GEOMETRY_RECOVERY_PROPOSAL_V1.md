# Proposed matched Donut recovery across oracle and reconstructed geometry

**Proposal only. Separate implementation, freeze and execution approval required.** Measure how replacing oracle geometry with the provenance-unverified historical Donut reconstruction changes material recovery. Gate 3 found 7.80% fitting and 5.54% held-out fixed-material common-support RGB relative L2 with small measured integration uncertainty. The comparison will test whether optimization compensates for the discrepancy through physically biased materials. [Gate 3 results](../results/publication_gate3/README.md)

## Four histories with two matched geometry pairs

| Pair | Oracle geometry | Historical reconstructed geometry |
| --- | --- | --- |
| K1-style reference | Corrected-core chart, native specular and diffuse sampling, accepted legacy material and white priors | Same recipe |
| Final-Ambient candidate | Ambient tensor predictor, validated tensor evaluator and world-Gaussian proposal, projected world-X weak start, accepted scalar-compatible and energy/specular/white priors | Same recipe |

Reuse each recipe without added surface-Q penalties, tuning or altered losses. Run K1 oracle/reconstructed, then ambient oracle/reconstructed. Use seed 6033 and the same fresh full-field neural weights within each geometry pair. Match the initialization rule, with the geometry-dependent physical start evaluated on each arm's actual positions and normals. Record initial weight hashes and physical predictions before updates. Cross-recipe differences also include initialization, rendering, sampling and priors. The geometry effect is the within-recipe paired difference. [Accepted K1 reference](BELL_DENSE_KNOWN_L2_RECOVERY_V1.md) · [Accepted ambient recipe](BELL_FINAL_TENSOR_PAIR_V1.md)

Use the same 15,191 fitting observations and 7,306 held-out observations in all four histories. The pool consists of fixed, row-major common hits with a valid Gate 2 transfer and positive facing on both meshes. Preserve the six camera IDs and record every excluded observation by reason. Retain valid camera 1 pixel 8,239. Fit the exact same admitted oracle RGB at those pixels in both geometries. The model receives the geometry-specific hit position and shading normal plus the same calibrated viewing direction. Recompute incident visibility on each mesh using the corrected BVH. Illumination is fixed analytic L2 with zero indirect and no point light, and the learned light networks remain inactive. The optimizer sees no oracle material labels, held-out RGB, Gate 3 predictions, or boundary supervision.

Keep the original linear Charbonnier objective, 512 fitting observations per update, native Adam/AMSGrad and warm-up/cosine schedule, gradient clipping and 10,000-update endpoint per history. Use an identical recorded fitting-index stream in all four histories. Use matched sampling seeds within each pair. Save the existing eight-draw diagnostics at initialization and every 2,000 updates. Run the accepted native compatibility gate at the same 24 common fitting pixels against each mesh's independently rendered fixed-material Gate 3 predictions for those pixels. Those predictions validate the integration interface and stay outside the objective. Verify finite native gradients, fixed-light routing, first-update boundaries and strict own-checkpoint roundtrip.

## Endpoints and limits

At the fixed 10,000-update endpoint, report within-recipe changes in Q median/p95, signed and absolute sorted-width errors, common-eligible orientation, albedo, metallicity, boundary jumps and RGB. Use geometry-specific archived labels for physical error and bring Q back to a common oracle tangent plane for paired comparison. Report local geometry-frame and material sampling shifts from Gate 2 separately. Retain identical fitting/held-out split, boundary-side classifications, grazing, degenerate-adjacent and large-depth cohorts. All undefined radiance and unmatched masks stay in the coverage record. Compare fitted RGB with the fixed-material discrepancy on the **same** known common support. Lower RGB error with worse physical recovery is evidence consistent with material compensation under this design. One seed and one reconstructed mesh limit generalization.

Proposed execution cap is 40,000 total Adam returns, at most 12,290 shader calls and 9,524,232,192 shadow-ray slots per history, including the existing 32-draw compatibility check, six eight-draw evaluations and allowance for two additional 24-point admission draws. No new primary rays, SDF fitting, reference integration, regularizers or architecture changes are required. Reuse the reviewed corrected image on A100 GPU 0 with four CPU threads, 64 GiB RAM without swap, 128 PIDs, 25% CUDA allocator and 8 GiB outputs per arm. Use the existing four-history foreground limit of 14,760 seconds with 30 seconds of kill grace, 3,600 seconds per arm and 3,540 seconds internally. Freeze exact counts and compatibility work after a source and metadata audit. Preserve partial results and stop on the first mandatory failure without retry or tuning. No training is authorized by this proposal.
