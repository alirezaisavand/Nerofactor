## External anisotropic comparison

The [published ShinyNeRF study](https://doi.org/10.5194/isprs-archives-XLVIII-2-W12-2026-33-2026) uses 68 training and 33 test views per scene in its expanded description. The audited [official source at 15c74e98](https://github.com/multimedia-eurecat/ShinyNeRF/tree/15c74e98eff684dc0f650b9ecaf00d6bdc19d40e) predicts density, normals and a tangent frame, then encodes reflected directions using a frozen ASG-to-vMF network and a learned directional RGB module. RGB is converted to sRGB and clamped per sample before compositing. The release has no explicit incident-light input to replace for calibrated relighting. Its configuration uses 6,000 rays per batch and sets a 1,000,000 maximum step budget. Publication-scale runtime, pinned new dependencies and review of the bundled ASG network weights are material costs. [Expanded method and experimental protocol](https://arxiv.org/html/2512.21692v1) · [Released config](https://github.com/multimedia-eurecat/ShinyNeRF/blob/15c74e98eff684dc0f650b9ecaf00d6bdc19d40e/configs/shinynerf/shiny_blender_bitangent_radius.gin)

## Full inverse rendering

1. **Oracle geometry with unknown direct illumination.** Existing heterogeneous Donut and Bell D2/D8 fits already jointly optimized directional light and material under zero indirect. Donut's held-out learned-light errors in linear RGB relative L2 were .1337/.2631/.1794 for D2/Chart/Tensor. The training-light map errors were .2110/.4024/.2759. These are measured recipe endpoints. The smallest new experiment is to independently relight those same Donut material exports at the existing unseen light, which this gate prepares. A future causal known-versus-unknown comparison should add a single learned-light counterpart to the exact Final-Ambient recipe on the identical Gate 4 observation pool, using the archived known-light control. Keep material initialization, sampling and budget matched, let only the declared directional light head train, and keep the true light out of the optimizer, initialization, regularizers, selection and shader compatibility. Use synthetic BRDF tests for any pretraining admission. [Donut evidence](../donut_heterogeneous_training_v1/README.md) · [Bell evidence](../bell_heterogeneous_training_v1/README.md)

2. **Authenticated geometry, then joint material and light.** Pinned G `79252178…` uses a staged NeuS-style SDF, original Trainer and periodic validation/save. Pinned A `e1e85977…` consumes an explicit mesh, computes the required frame conventions and supports directional light. The corrected core has separately audited known-light/zero-indirect routing. Final-Ambient uses its independent tensor decoder and common Beckmann/Gaussian shader on explicit geometry. The existing handoff checks scene, geometry source manifest, producing run, mesh hash, orientation and material preprocessing. The historical Donut file has neither an authenticated checkpoint nor a producing extraction manifest. The Bell two-update reports authenticate the training prefix only. Historical Bell checkpoint compatibility and r128 extraction identify the extraction procedure, and the archived zero-level/normal gates failed on those data. None is a valid replacement G handoff.    Bypass missing provenance by a **fresh pinned G run on admitted Bell v3**. Its synthetic loader already consumes the camera/RGB/mask/depth formats. The historical split reserves camera 0 only, so an explicit acquisition adapter must enforce Bell v3's 122/1/5 split at every getter without changing the loss or optimizer. Verify the natural 1,000-step save/validation boundary as the first separately bounded lifecycle milestone. A paper geometry result needs a prospectively fixed schedule that reaches the later G loss phases, one predefined endpoint, and complete producer/seed/split/calibration/checkpoint/mesh identities. Extract one explicitly selected checkpoint using the pinned SDF code and frozen bounds, winding and resolution. Validate signed normals, SDF crossing, closest-hit visibility and silhouette/depth/normal parity on Bell v3 before material fitting. Archive failed geometry separately. Use the accepted G mesh for both project recipes. Begin with one reconstructed-geometry K1-style learned-light history compared to its exact oracle counterpart on predeclared common raster support. Admit ambient next only after the same handoff, with preserved frame transport. Evaluate oracle and G geometry on the same held-out views and under the same unknown-light regime. Gates 2–4 remain historical geometry-sensitivity evidence. [Gate 4](../publication_gate4/README.md) · [E.10 corrected material routes](../../NATIVE_MATERIAL_A_CORRECTIONS_E10.md)

3. **Light scale and unseen-light evaluation.** Material/illumination compensation may shift amplitude and color even with known cameras. Report raw HDR environment errors, spherical mean RGB, and a single scalar gain-aligned diagnostic evaluated after fitting. This scalar changes the diagnostic map only. It preserves non-global differences and supplies no training calibration. Avoid per-channel alignment, GT light/exposure fitting, or checkpoint selection against GT. For real-data experiments, an independently measured light probe or calibrated grey card can anchor amplitude as a separately disclosed acquisition input. Evaluate independent unseen illumination at fixed sensor exposure with frozen Q, widths, color and metallic. On reconstructed geometry retrace visibility and report common, excluded and full-raster masks. Separate fixed-material geometry discrepancy from learned material compensation.
